# Converge the document/control system

1. Run `tools/bin/lenbands context --yaml`; `DOCS.yaml` is the machine authority resolver.
2. Build a field-level drift ledger for the requested scope: canonical owner, authority state, retrieval state, executable consumers, agent-routing consumers, severity and disposition.
3. Fan out disjoint read-only audits when useful. Role-separated passes are veto gates, not independent human review or authority.
4. Converge product/IELTS semantics, API/data/event/failure/privacy contracts, runtime invariants, sourcing, NFRs, evidence policy, UX/accessibility and operations without preselecting a production language, queue, cache, broker or provider.
5. Keep provider candidates in sourcing/procurement artifacts. Runtime semantics remain provider-neutral and buy-first; custom infrastructure requires an evidence-backed exception decision.
6. Preserve the four distinct states: scope lifecycle, implementation eligibility, implementation authorization and release readiness. Do not infer one from another.
7. Before deleting/demoting an old authority, prove reference closure across validators, generators, context builders, skills, agents, manifests and docs.
8. External facts require primary authoritative citations. Never convert citations, model output, YAML claims or prose into benchmark/acceptance evidence.
9. Do not edit application source while the trust policy source lock is active. Tool availability and repository verification do not authorize implementation.
10. After each coherent batch run `tools/bin/lenbands verify` and `tools/bin/lenbands gate toolchain`; `gate p0` remains allowed to block on genuine evidence gaps.

The final handoff lists resolved authority conflicts, validator coverage, non-authoritative historical residue, remaining external/evidence blockers, and the exact candidate SHA. Never self-declare approval, calibration, production readiness or “god level” from prose alone.
